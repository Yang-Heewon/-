# E2E 스트림 본시합 — 사전등록 (M7 후보)

등록일: 2026-08-20 (실행 전 박제) · 대상: GVM(게이트형 시각 기억) 전체 시스템 vs 기준 정책들

## 1. 검증 질문

화면 관찰이 시간순으로 흐르고 일부 화면이 개정되는 스트림에서, 같은 총 byte 예산일 때 GVM(훈련 없는 게이트들)이 단순 정책들보다 "최신 기준 정답"을 더 많이 지키는가 — 그리고 전량 보관 대비 비용을 얼마나 줄이는가.

## 2. 테스트베드 (반실환경, 결과 25-B 생성기 확장)

- Chrome 렌더 5템플릿(dashboard/inbox/settings/table_report/article), 고정 헤더에 시계(모든 관찰이 픽셀 차이를 가짐), 관찰마다 랜덤 세로 스크롤(0~600px).
- 에피소드 = 12관찰 스트림: 5페이지가 섞여 등장, 페이지당 1~4회 재방문, 재방문 시 확률 0.5로 필드 1개 개정(개정 이력 기록).
- 질문: 스트림 종료 후 페이지당 2문(개정 필드 1 + 비개정 필드 1), gold = **관찰 이력상 최신 값**. 20 에피소드 × 10문 = 200문.
- 시드 고정(20260820), 생성 후 수정 금지.

## 3. 정책 (동일 총예산 = 관찰수 × B, B ∈ {8KB, 24KB})

| 정책 | 쓰기 규칙 | 예산 초과 시 |
|---|---|---|
| no_memory | 저장 없음 | — |
| keep_everything | 모든 관찰 전체 AVIF (예산 무시) | — (천장·비용 기준점) |
| uniform | 관찰마다 B로 전체 화면 압축(안 되면 저장 실패) | 가장 오래된 저장물 삭제(FIFO) |
| **GVM** | 재방문 감지(마스크→정렬→diff): 무변경→저장 생략, 변경→**패치만** 저장(옛것 유지); 신규 페이지→feasibility 기반 전체 저장 | 페이지별 옛 리비전부터 강등(썸네일)·삭제 |
| text_only | 필드 라벨:값 텍스트 덤프(완전 OCR 가정 — 텍스트에 유리한 설정임을 명시) | — |

읽기: 질문 페이지에 대해 각 정책이 보유한 저장물을 시간 메타데이터와 함께 주입(결과 24 직렬화 규약), Qwen2.5-VL-7B가 답. 판정: 최신 값 EM.

## 4. 사전등록 가설 (실행 전 박제 — 실패해도 그대로 보고)

- **H1 (입력+망각의 예산 효과)**: 빠듯한 예산(B=8KB)에서 GVM 정확도 ≥ uniform + **15pp**
- **H2 (낡음 제거)**: 개정된 필드 질문에서 GVM의 낡은 값 답변 비율 ≤ **5%**, uniform(옛 저장물이 살아남는 경우) ≥ **30%**
- **H3 (비용)**: GVM 총 byte ≤ keep_everything의 **50%**, 정확도 격차 ≤ **2pp**
- **H4 (안정성)**: 같은 페이지의 저장↔삭제 반복(진동) **0건** (GVM 내부 이벤트 로그로 측정)
- **H5 (텍스트 한계)**: text_only는 완전 OCR 가정에도 비개정 질문에서 GVM과 동률 이상이나, 이 설정이 실환경 OCR(글자 인식 오류)보다 유리함을 명시 — 보조 비교로만 사용

## 5. 판정 규칙

H1·H2·H3 모두 충족 → GVM 주장 성립(M7 승격 후보). 하나라도 실패 → 실패한 가설과 원인 분석을 결과에 그대로 기록(수치 조정 후 재등록 금지, 재설계는 새 등록으로).
