# 게이트형 시각 기억(Gated Visual Memory) — 검증 보고서

작성일: 2026-08-19 · 실행: 로컬 V100 GPU 2·3 + CPU 분석 · 원데이터: `results/discovery/gates/`, `results/discovery/md_scaled_read.*`

## 0. 프레임 정의

**게이트형 시각 기억**: 에이전트의 장기 시각 기억을 LSTM(장단기 기억 신경망)의 *동작 원리*처럼 — 정보가 세 개의 관문(게이트)을 통과하며 선별적으로 흘러가는 시스템으로 — 설계하자는 프레임. 단, LSTM처럼 고정 크기 잠재 벡터에 눌러 담는 것이 아니라, **명시적 계층(원본 사진 아카이브 / 텍스트 색인 / 핫 캐시) 위에서 게이트가 흐름을 제어**한다.

| 게이트 | 결정 | 대응하는 우리 발견 |
|---|---|---|
| 입력 게이트 | 새 화면을 무엇으로, 몇 byte로 저장할까 | 화면별 필요 예산 16배 편차 (motivation ②) |
| 망각 게이트 | 기존 기억 중 무엇을 낡음 처리할까 | 낡은 기억의 조용한 거짓말 (motivation ①) |
| 출력 게이트 | 질문에 어느 기억을 얼마나 읽을까 | 확신도 게이트 (AUROC 0.73~0.81, 기검증) |

이 보고서는 입력·망각 게이트를 데이터로 검증한 기록이다. 출력 게이트는 기존 캐스케이드 실험에서 이미 검증되었다.

## 1. 입력 게이트 — 신호 검증 (1단계)

**질문**: 화면을 모델에 넣어보지 않고도, 싼 신호만으로 "이 화면에 몇 byte가 필요한지" 알 수 있는가?

**방법**: 기존 코덱 곡선 실측(GUI 165장 + 자연 211장, 각 이미지 × 예산 4점의 정답 유지율)에서 이미지별 **필요 예산**(전체 화질에서 맞히던 답이 그대로 유지되는 최소 byte)을 뽑고, 쓰기 시점에 공짜인 신호와 순위상관(스피어만)을 측정. 코드: `vlm_diagnosis/scripts/gate_input_analysis.py`, 결과: `gates/input_gate.json`.

**필요 예산 분포** (편차의 실재):

| 데이터 | 8KB면 충분 | 32KB 필요 | 128KB+ 필요 |
|---|---|---|---|
| GUI (SQA 165장) | 39장 | 123장 | 3장 |
| 자연 (GQA 211장) | 188장 (2KB 충분 40 포함) | 17장 | 6장 |

**신호 상관** (필요 예산과의 스피어만 순위상관):

| 신호 | GUI | 자연 |
|---|---|---|
| 원본 파일 크기 | **0.68** | 0.32 |
| 해상도(픽셀 수) | 0.62 | 0.12 |
| OCR 글자 byte | 0.26 | 0.12 |

**판정**: GUI에서는 파일 크기·해상도라는 공짜 신호가 필요 예산을 상당히 예측한다(입력 게이트 실현 가능). 자연 이미지에서는 약하다 — 자연용 게이트 신호는 열린 문제.

## 2. 입력 게이트 — 예산 경제 (2단계)

**질문**: 같은 총예산에서, 게이트가 화면별로 차등 배분하면 균등 배분을 이기는가?

**방법**: 총 byte 고정 후 세 정책 비교. *오라클* = 미래 점수를 미리 아는 이상적 배분(이론 상한). *신호 배분* = 미래 점수는 차단(5-fold 교차검증)하고, 글자량 신호 + "압축이 캡에 안 들어가는지"(쓰기 시점에 압축기를 돌려보면 공짜로 아는 정보)만 사용. 배분기는 byte당 이득 내림차순 탐욕 + 오목 껍질(이득 0인 계단 건너뛰기).

| 조건 | 균등 | 신호 배분 | 오라클(상한) |
|---|---|---|---|
| GUI, 평균 8KB/장 | 0.261 | **0.436** | 0.436 |
| GUI, 32KB/장 | 0.991 | 0.988 | 0.997 |
| 자연, 8KB/장 | 0.912 | 0.912 | 0.965 |
| 자연, 32KB/장 | 0.979 | 0.979 | 0.995 |

**판정**:
- 예산이 빠듯한 GUI에서 게이트 배분이 균등 대비 **+67% (0.26→0.44), 오라클 상한에 도달**. 이득의 원천은 "안 들어가는 화면에 억지로 주지 않고, 되는 화면에 몰아주기".
- **이득의 귀속 분해 (재검증, 2026-08-19)**: 글자수 신호를 완전히 빼고 "압축이 캡에 들어가는지"라는 쓰기 시점 관찰만으로 배분해도 0.433 — 신호를 더해도 0.436. 즉 **+67%의 사실상 전부가 feasibility(들어가나 안 들어가나) 재배분에서 오고, OCR 글자수 신호의 추가 기여는 무시 가능(+0.003)**. 1단계의 상관(파일 크기 ρ=0.68)은 실재하지만, 현 예산 격자(8/32/128KB)에서는 배분 이득으로 번역되지 않는다. 논문 서술 시 공로는 "무료 feasibility 관찰"에 두어야 정직하다.
- 예산이 넉넉하면 이득이 소멸 — 입력 게이트는 **총예산 부족 국면의 기술**이라는 적용 조건이 명확.
- 자연에서는 오라클 이득(+5.2pp)이 존재하나 현재 신호로는 미실현 — 신호 연구 여지.

## 3. 망각 게이트 — 변화 감지기 (3단계)

**질문**: "이 화면, 지난번과 달라졌나 + 어디가 달라졌나"를 모델 호출 없이 알 수 있는가?

**방법**: memory_dynamics 픽스처(controlled 32 + scaled 64 = 96쌍; 변경 48/무변경 48)의 옛/새 화면에 16px 타일 평균차 감지기 적용. 화면에는 스냅샷 번호·관찰 시각이 그려져 있어 **무변경 쌍도 픽셀은 반드시 다름** — "픽셀이 다르면 낡음"이라는 순진한 규칙은 구조적으로 시험대에 오른다. 코드: `gate_forget_detector.py`, 결과: `gates/forget_gate.json`.

| 감지기 | AUROC | 최적 임계 정확도 | 비고 |
|---|---|---|---|
| 순진(전체 화면 max) | 1.00 | 1.00 | 변경 min 63 vs 무변경 max 23 — 이번 픽스처에선 우연히 분리 |
| 내용영역 한정 | 1.00 | 1.00 | 무변경 점수 정확히 0 — 마진 무한대 |

- **변경 위치 찾기: 48/48 적중** → "어느 값이 낡았나"까지 공짜 → 부분 무효화의 재료
- 비용: **쌍당 30ms, CPU 순수 파이썬** (numpy화하면 ms 미만)
- 한계: 합성 화면이라 픽셀 정렬이 완벽. 실제 GUI(스크롤·애니메이션·리사이즈)에선 정렬 문제가 추가된다. 이 결과는 "정렬된 재관찰"이라는 조건부 기제 검증이다.

## 4. 망각 게이트 — 실전 효과, 2배 규모 (4·5단계)

**방법**: 확장 픽스처(64에피소드, seed 777 — 기존 controlled 32ep의 독립 재생성 2배 규모)를 GPU 2·3에 샤드 분할해 640 trial 전량 실행(Qwen2.5-VL-7B, 무손실 copy 코덱). 시간 조건 4개(낡은 기억만 / 새 기억만 / 둘 다 / 기억 없음) × 변경 여부. 이어서 3단계 감지기와 결합한 **게이트 정책**(감지기가 "바뀜"이라 하면 새 화면을 읽고, 아니면 기존 기억 유지)의 성적을 실측 trial의 정확한 합성으로 계산. 코드: `gate_forget_synthesis.py`, 결과: `gates/forget_gate_synthesis.json`.

| 조건 (n=32씩) | 낡은 기억만 | 새 기억만 | 둘 다 | 기억 없음 | **게이트 정책** |
|---|---|---|---|---|---|
| 내용 변경됨 | **0.000** | 1.000 | 1.000 | 0.063 | **1.000** |
| 변경 없음 | 1.000 | 1.000 | 1.000 | 0.031 | **1.000** |

핵심 수치:
- **조용한 거짓말이 2배 규모에서 완전 재현**: 변경된 32에피소드 전부(32/32)에서 낡은-기억 조건이 **옛 값을 그대로 답함** (16/16 → 32/32, 합계 48/48). 오답이 아니라 "한때 정답이었던 값"이라 겉보기 그럴듯함 — 확신도로는 못 잡는 실패(기존 D4 분석).
- **게이트 정책 정확도 1.000** (감지기 64/64 + 조건별 실측의 합성).
- "둘 다 보관"도 정확도 1.0이지만: 저장 2배, **읽기 시간 2배**(중앙값 2.1s vs 게이트 1.1s). 개정이 쌓일수록 이 비용은 선형 증가 — 게이트는 상수 유지.
- 확장판에서도 검색(후보 1/2/4)·간섭(방해꾼 0/1/3) 전 셀 만점 → **이 규모의 실패는 오직 시간축**. 진단 프로그램의 "실패는 어디서 오는가"에 대한 답이 더 좁혀짐.
- **압축된 기억에서도 동일**: AVIF 코덱 패스(평균 패키지 21.6KB — 무손실 copy 대비 약 1/10)에서 4조건 정확도가 copy와 완전히 같음(낡은기억만 0.0/1.0, 새기억만 1.0, 둘다 1.0, 낡은 답 32/32). 게이트 정책도 1.0 유지 — **망각 게이트의 결론은 저장 형식·압축률과 독립**.

## 5. 종합 판정

1. **세 게이트 모두 데이터 근거 확보**: 입력(빠듯한 예산에서 +67%, 상한 도달) · 망각(조용한 거짓말 48/48 → 게이트로 1.0 회복) · 출력(기검증 AUROC 0.73~0.81).
2. **게이트는 전부 훈련 불필요**: 압축기 실행 결과 + 파일 크기 + 픽셀 타일 비교 + 로짓 마진. 학습형 게이트 선행(TaskMem 등 +5~7%)과의 차별점.
3. 적용 조건도 정직하게 확정: 입력 게이트는 **총예산 부족 국면**에서만 가치, 망각 게이트의 감지기는 **정렬된 재관찰** 조건 검증(실환경 정렬 문제는 열림), 자연 이미지용 입력 신호는 미해결.

## 6. 한계와 다음 단계

- 망각 게이트 실측은 합성 대시보드(단일 도메인·완벽 정렬) — 실제 GUI 궤적으로의 확장이 승격 조건.
- 입력 게이트의 자연 이미지 신호(오라클 +5.2pp 미실현) 탐색.
- 승격/강등의 진동(thrashing) 안정성은 미검증 — 스트림 시뮬레이션 필요.
- M7 사전등록 후보 문장: "정렬된 재관찰 스트림에서, 훈련 없는 3게이트 정책은 (a) 빠듯한 총예산에서 균등 배분 대비 유지율 ≥+X pp, (b) 낡은-기억 오답을 ≥Y% 제거하며, (c) 전량 보관 대비 저장·읽기 비용 절반 이하."
