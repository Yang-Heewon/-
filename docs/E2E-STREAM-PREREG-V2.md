# E2E 스트림 본시합 v2 — 사전등록 (강등 연산자 교체 + 기억 강도 승강)

등록일: 2026-08-20 (실행 전 박제) · 선행: v1 (docs/E2E-STREAM-PREREG.md, H3 실패 — 썸네일 강등의 판독 저하)

## 1. v1에서 바꾸는 것 — 딱 두 부품

**(가) 강등 연산자: 해상도 축소 → 콘텐츠 적응형 3단 사다리**

| 단 | 형태 | 예상 byte | 근거 |
|---|---|---|---|
| R0 | 전체 해상도 AVIF (품질 자동, ≤24KB 캡) | 14~24KB | v1과 동일 |
| R1 | **전체 해상도 최저품질 AVIF + 필드 텍스트 덤프** | ~13.6KB + ~1KB | 전량보관이 저품질에서 0.980; 텍스트 비개정 0.927 |
| R2 | **텍스트 덤프만** (이미지 삭제) | ~1KB | 최후 잔존, 삭제 금지 |

- v1의 25%면적 썸네일(판독 붕괴 원인) 폐지.
- 텍스트 덤프 = 저장된 최신 리비전 기준 필드 값(완전 OCR 가정 — text_only와 동일 가정임을 명시). 패치가 있으면 패치 반영값.
- 패치는 기저 스냅샷과 함께 승강.

**(나) 강등 순서: FIFO → 기억 강도 점수 (LSTM식 게이트 값의 결정 함수)**

예산 초과 시 강도가 낮은 것부터 한 단씩 강등:
> 강등 우선순위 = ① 대체된(superseded) 리비전 먼저 → ② 마지막 사용/관찰 후 오래된 순 → ③ 동률이면 오래된 스텝 순

- **사용 강화**: 스트림 중간 질문(하단)에서 검색된 페이지의 저장물은 나이 리셋(LSTM 입력 게이트의 강화에 대응).
- **히스테리시스**: 같은 스텝에 사용된 저장물은 그 스텝에 강등 금지; 직전 스텝에 강등된 저장물은 연속 강등 금지.
- 이 테스트베드는 전 화면이 글자 중심이라 콘텐츠 유형 축(글자/시각)은 발동하지 않음을 명시 — 유형 축 검증은 자연 이미지 혼합 스트림(추후 등록)의 몫.

## 3. 사전등록 가설 (박제 — 실패해도 그대로 보고)

- **H1′ (v1 H3 재도전)**: @24KB — GVM-v2 총 byte ≤ keep의 50% **그리고** 최종질문 전체 정확도 격차 ≤ **2pp**
- **H2′ (빠듯한 예산 회복)**: @8KB — GVM-v2 전체 정확도 ≥ **0.85** (v1: 0.640)
- **H3′**: 낡은 답 비율 ≤ **5%** (양 예산)
- **H4′**: 진동(같은 저장물의 승강 왕복 ≥3회) **0건**
- **H5′ (사용 강화, 보조·방향성)**: 중간 질문에서 사용된 페이지의 최종질문 정확도 ≥ 미사용 페이지 (@8KB에서 판정)

판정 규칙: H1′·H2′·H3′·H4′ 전부 충족 → GVM-v2 성립(M7 승격 후보). 실패 시 원인 분석과 함께 그대로 기록, 수치 사후 조정 금지.
