# 파일럿 결과 종합 — 시각 기억 압축은 어디서, 왜 실패하는가

> **지위**: 모든 수치는 파일럿(smoke)이다 — DocVQA 문서 32장, seed 1개, 질문 쌍 유형
> 라벨(T0–T4) 없음, 이미지 단위 신뢰구간 없음. 프로토콜 규칙에 따라 discovery 결과로
> 승격하지 않는다. 방향은 선명하지만(주 격차 = 측정 잡음의 15배 이상) 논문 수치는 아직
> 아니다.
>
> **읽는 법**: 각 결과를 [어떤 상황을 만들었나 → 숫자 → 왜 이런 일이 생기나 →
> 무엇을 의미하고 무엇을 의미하지 않나] 순서로 쓴다.

## 0. 이 연구가 시뮬레이션하는 상황

에이전트의 실제 시나리오는 이것이다:

```text
[어제]  에이전트가 문서 사진 하나를 처리했다.
        모델이 사진을 읽으면 내부에 중간 계산 결과(KV)가 생긴다 — 사진당 약 1,260개.
        이걸 다 저장하면 비싸니, 일부(예: 20%)만 남기고 영구 삭제해야 한다.
        → 문제: 무엇을 남길지 고르는 순간, 내일 무슨 질문이 올지 모른다.

[오늘]  같은 문서에 대해 새 질문이 왔다.
        어제 남겨둔 조각만으로 답해야 한다. 지워진 부분은 복구 불가능하다
        (원본 사진도 안 갖고 있는 상황을 가정).
```

| 용어 | 뜻 |
|---|---|
| KV | 모델이 이미지를 읽을 때 생기는 중간 계산 결과. 시각 토큰당 1개. 저장해두면 이미지를 다시 계산하지 않고 재사용 가능 |
| 예산 B | 남기는 비율. bytes 기준(색인·위치 정보 포함). B=20% = 1,260개 중 약 252개만 보존 |
| selector | "어느 것을 남길지" 고르는 규칙 |
| 대리 지표 | 미래 유용성은 잴 수 없으므로 selector가 대신 쓰는 근사 신호 (3장) |
| 유지율 | 무압축 기억으로 맞힌 질문 중, 압축 후에도 맞히는 비율. 모델이 원래 못 푸는 문제를 압축 탓으로 세지 않기 위한 조건부 채점 |
| EM / ANLS | 채점: 완전 일치 / DocVQA 공식 편집거리 유사도 |

## 1. 준비 운동 — 이 측정을 믿어도 되는가 (M0)

본실험 전에, 도구가 만드는 가짜 현상이 없는지 네 가지를 확인했다.

### 1-1. 모델이 애초에 풀 수 있는 과제인가

이미지를 직접 보여주고 채점: 글자 읽기 1.00 / 도형 색깔 1.00 / 좌우 배치 1.00 /
좌표 짚기 0.60.

좌표의 0.4 실패는 형식 문제가 아니었다 — 예측을 뜯어보니 실패 4건 중 3건이 전부
"정답은 화면 상단(y=120)인데 모델은 하단(y=800)이라 답함" 패턴이었다 (x축은 정확).
**이 모델은 상단 물체의 y좌표를 아래로 미는 체계적 편향이 있다.** 도구가 아니라 모델의
특성이므로, 좌표 과제는 "기준 경로가 맞힌 표본만으로 기억 효과를 계산"하는 조건부
규칙으로 다룬다.

### 1-2. 이미지가 정말 필요한 과제인가

시각 정보를 전부 가리면 점수 −0.78, 이미지 없이 질문만 주면 0.00. → "기억 없이는 못
푸는" 과제 집합이다. 이 확인이 없으면 "압축해도 점수 유지"가 "애초에 이미지를 안 쓰는
문제였음"일 수 있다.

### 1-3. 지우는 시점의 함정 — 정보 밀수

입력은 한 줄로 이어져 있다: `[시스템][이미지][질문][답]`. 질문 토큰은 처리되는 동안
이미지를 참조하므로, **질문 토큰 자신의 KV 안에 이미지 정보가 섞여 들어간다.**

그래서 이미지 정보를 100% 지워도, *언제* 지우느냐로 성적이 갈린다:

```text
V1 (질문이 이미지를 본 뒤 지움):  0.50  ← 질문 KV로 새어든 정보로 절반을 맞힘 (부정행위)
V2 (질문이 오기 전에 지움):       0.12  ← 실제 시나리오와 일치 (0이 아닌 건 찍기 성공분)
```

V1로 재면 압축 피해를 4배 과소평가한다. **모든 실험은 V2로 고정** (과거 실험이 무효
처리된 이유 중 하나).

### 1-4. 잡음의 자

계산 경로를 합법적으로 바꿔도(저장→디스크→복원→이어 계산, 쪼개서 계산) 로그확률 차이는
최대 ~0.15 nat이고 **모델의 답 선택은 40/40 불변**. 가림 장치를 켜고 100% 보존하면
차이가 정확히 0. → 이보다 작은 차이는 효과로 해석하지 않는다. 이후의 주 격차(수십 %p)는
이 잡음의 수십 배다.

## 2. 압축하지 않으면 아무 문제가 없다 (M1)

| 조건 | 정답률 |
|---|---:|
| 기억 없음 (질문만) | 0.00 |
| 원본 이미지를 다시 보여줌 | 0.94 |
| **무압축 KV를 저장→디스크→복원→주입** | **1.00** |
| 시각 KV만 (시스템 prefix 행 제외) | 0.75 |
| 기억-질문 사이 거리를 +2048토큰 벌림 | 0.94–1.00 |

**의미**: 저장·재사용 경로 자체는 완벽하다. **이후 나오는 모든 실패는 "압축" 때문이다.**

**의미하지 않는 것**: 시각 KV만 저장 시 하락(0.75)과 거리 견고성은 표본 16개짜리 방향
신호일 뿐이고, 특히 거리 실험은 "위치 번호만 민 것"이라 실제 텍스트가 사이에 낀 상황
(간섭)과 기억 블록 자체의 이사(재회전 필요)는 별개 질문으로 남아 있다.

## 3. 압축하면: 어떤 "대리 지표"를 쓰든 강한 압축에서 실패한다 (M2-A)

### 대리 지표란

저장하는 순간 "미래 유용성"은 잴 수 없다. 그래서 모든 selector는 다른 신호로 그것을
근사한다. 도서관에 책을 반납하기 전 몇 페이지만 찢어 보관한다고 하면:

| selector | 무엇을 보고 고르나 (비유) |
|---|---|
| random | 아무 페이지나 |
| spatial_uniform | 골고루 한 장씩 |
| knorm | 잉크가 진한 페이지 (신호의 물리적 크기) |
| **s5** (KVzip 적응) | **"줄거리 요약을 써보고, 그때 참고한 페이지"** — 범용 과제에의 쓸모 |
| **h2o** (H2O 적응) | **"예전 질문에 답할 때 펼쳤던 페이지"** — 과거 사용 이력 |
| s1 (반칙 참조선) | "내일 시험 문제를 미리 보고 그에 필요한 페이지" |

### 결과: 20% 예산에서의 유지율 (무압축이 맞힌 89질문 기준)

```text
s1 (미래 질문을 봄 — 반칙)      0.99 ██████████████████████
s5 (요약에 쓰인 것)             0.61 █████████████
h2o (과거에 쓰인 것)            0.51 ███████████
spatial_uniform (골고루)        0.45 ██████████
random (아무거나)               0.44 █████████
knorm (신호 크기)               0.17 ████        ← 무작위보다 나쁨 (부호 검증 전 보류)
```

예산을 더 조이면 (s1과 random만 확장 측정):

| | 5% | 10% | 15% | 20% | 40% | 60% | 80% |
|---|---:|---:|---:|---:|---:|---:|---:|
| s1 | 0.84 | 0.90 | 0.93 | 0.99 | 1.00 | 0.99 | 0.99 |
| random | 0.18 | 0.25 | 0.34 | 0.44 | 0.70 | 0.82 | 0.94 |

### 이 표에서 읽어야 할 세 가지

1. **용량은 병목이 아니다.** 질문을 알면 5% 예산(1,260개 중 62개)으로 84%를 지킨다.
   질문 하나의 근거는 기억의 극히 작은 조각에 담긴다.
2. **저장 시점에는 아무도 그 조각을 못 고른다.** 대리 지표 중 최고(s5)가 0.61 —
   반칙 참조선과 38%p 차이.
3. **약한 압축(80%)은 거의 무해하다** (0.85–0.96). 이 실패는 강압축(5–40%) 구간의
   현상이다.

**의미하지 않는 것**: s5·h2o는 원논문의 시각 적응판이다(원본 그대로가 아님 — 결과표에
항상 적응 딱지). knorm의 역효과는 적응의 부호 관례 확인 전까지 주장하지 않는다.

## 4. 핵심 발견 ① — 한 질문용 집합의 재사용은 붕괴한다

### 만든 상황

```text
[어제] 질문 A("회사 이름은?")를 알고, A에 필요한 부분 위주로 20%를 남김  ← "한 질문용 집합"
[오늘] 같은 문서에 다른 질문 B("아타 브랜드는?")가 옴 → 어제의 20%로 답함  ← "재사용"
```

### 숫자

| 어제 저장한 20%를 어디에 쓰나 | 유지율 |
|---|---:|
| 같은 질문 A (질문이 반복된 경우) | 0.99 |
| **다른 질문 B (질문이 바뀐 경우)** | **0.59** — 40%p 추락 |
| (5%만 남겼다면, 다른 질문에서) | 0.24 — 무작위(0.18)와 거의 동일 |

### 왜

질문마다 문서에서 쳐다봐야 하는 **영역**이 다르다. "회사 이름"의 근거는 로고 영역,
"아타 브랜드"의 근거는 식품 문단. A 기준으로 고르면 B의 근거 영역은 "A에 불필요"로
분류되어 이미 지워져 있다.

### 의미

"과거 질문에서 중요했던 것을 남기자"는 실제 시스템들의 표준 전략(SnapKV·H2O 계열)이
**질문이 반복되는 동안만 유효하고, 질문이 바뀌면 무작위 수준으로 무너진다**는 것.
텍스트 LLM에서 KVzip이 발견한 붕괴(95%→60%, 35%p)와 같은 현상을 시각 기억에서 통제
조건(같은 문서·같은 예산·질문만 교체)으로 재현했고 규모도 유사하다(40%p).

## 5. 핵심 발견 ② — 질문을 셋이나 겪어도 미래 질문은 못 덮는다

### 만든 상황

"질문 하나로는 부족해도, 여러 질문을 겪고 나면 이 문서의 중요한 곳을 알게 되지
않을까?" — 에이전트 메모리 설계의 자연스러운 기대다. 시험했다:

```text
[과거]  질문 1·2·3을 겪음 → 각 질문의 20%(또는 5%) 집합을 합쳐 pool을 만듦
        (집합들이 서로 1/3쯤 겹쳐서, 합쳐도 크기는 약 1.5~2배: 9%/29%)
[미래]  pool을 만들 때 전혀 안 쓴 질문 4·5로 평가 (held-out)
        공정 비교: 같은 크기의 무작위 집합, 같은 크기의 s5 집합도 함께 평가
```

### 숫자

| pool을 어디에 쓰나 | ~9% 크기 | ~29% 크기 |
|---|---:|---:|
| **그 세 질문에** (pool이 아는 질문) | 0.85 | 0.99 |
| **안 본 질문 4·5에** | **0.14** | **0.54** |
| (대조) 같은 크기 무작위 | 0.14 | 0.40 |
| (대조) 같은 크기 s5 — 질문을 하나도 안 씀 | 0.29 | 0.43 |
| (기준) 안 본 질문의 무압축 정답률 | 0.83 | 0.83 |

### 실물 예시 (ITC 광고 문서, 질문 9개)

pool은 소스 질문들의 근거(연도 표기, 퍼스널케어 브랜드 문단…)를 담았다. 안 본 질문
"의류 브랜드 2개는?"의 근거 문단은 pool에 없다. 모델의 답: **"Classmate and
Paperkraft"** — 지워진 근거 대신, **남아 있는 다른 브랜드 이름을 그럴듯하게 재활용한
오답**이다. 근거가 지워진 기억의 실패는 "모르겠다"가 아니라 이런 형태로 나타난다
(정확도만이 아니라 행동이 왜곡되는 문제 — loyalty).

### 의미

- 아는 질문들에서 완벽했던 pool(0.99)이 안 본 질문에서 9% 크기면 **무작위와 동일**,
  29%로 키워도 유지율 65%다. 4장에서 "만능 pool이 존재하는 듯" 보였던 것은 **아는
  질문들에 대한 과적합**이었다.
- 가장 아픈 줄: 과거 질문 3개를 아는 pool(0.14)이 **질문을 하나도 안 쓴 s5(0.29)보다
  나쁘다.** "경험이 쌓이면 좋아진다"가 아니라 "과거 질문에 과적합될 뿐"이다.
- **결론(파일럿)**: 실패의 원인은 고르는 요령이 아니라, **미래 질문이 요구할 근거가
  과거 경험(질문 이력 포함)으로부터 예측되지 않는다**는 것.

## 6. 방법론 발견 — "하나 빼보기"식 중요도는 중복 앞에서 거짓말을 한다

"정답까지 알려줄 테니 최적의 조각을 찾아와라"라는 진단 도구(answer-aware probe)를
만들었다. 탐색법: 2×2 패치(토큰 4개 묶음)를 하나씩 가려보고, 가렸을 때 정답 확률이
떨어지면 중요한 패치로 판정.

**결과: 모든 패치의 하락값이 0이었고**, 그 순위로 만든 probe의 성적은 예산을 5→40%로
늘려도 0.75에서 평평했다 — 같은 질문에서 s1이 1.00을 달성했으므로 이 숫자는 상한일 수
없다. 계획서에 미리 넣어둔 규칙("탐색법에 따라 결론이 바뀌면 판정 불가")에 따라 폐기.

**왜 전부 0이었나 — 낱개의 영향력이 없어서가 아니다.** 답이 적힌 페이지가 두 장인
책에서 한 장씩 찢어보면: 1페이지를 찢어도 2페이지가 답해주고, 2페이지를 찢어도
1페이지가 답해준다 → 낱개 측정으로는 둘 다 "중요도 0". 하지만 **둘 다 찢으면 답이
사라진다.** 즉 근거 패치의 영향력은 실재하지만 **백업이 남아 있는 동안에는 낱개 제거로
보이지 않는다.** 중요도는 낱개의 성질이 아니라 집합의 성질이다.

이 교훈은 이 연구 전체의 반복 주제와 같은 결이다: 낱개 점수의 합으로 집합을 고르는
모든 방식(우리 probe의 탐색뿐 아니라 3장의 대리 지표들도)은 중복·상호보완 구조를 놓친다.
probe는 집합 단위 탐색(s1 집합에서 출발해 교환 개선)으로 교체 예정.

## 7. 격차의 해부 — 숫자들을 하나의 그림으로

20% 예산 기준:

```text
random ──────────────── s5 ──────────────────────────────── s1 ─── (진짜 최적)
 0.44                  0.61                                0.99      ≤1.00
   └── 17%p ──────────────┘└──────────── 38%p ────────────────┘
   "대리 지표 개선이                "남은 격차 — 더 좋은 지표가 있는데
    이미 닫은 몫"                    못 찾은 것인가, 원리적으로 예측
                                     불가능한 것인가?"
```

- **s1은 진짜 최적(oracle)이 아니라 그 하한이다** (s1 ≤ oracle ≤ 1.00). 20%에서는
  s1=0.99라 위 공간이 1%p뿐 → "격차는 **최소** 38%p"가 사실상 확정.
- **5% 구간 실측 (수리된 probe, 12문서 완성)**: s1 초기집합에서 출발한 집합 교환
  탐색이 EM 0.83 → **0.92**로 개선 (14533은 s1 오답 → 교환 후 정답 +12.2 nats,
  284는 +33.5 nats). 즉 5%에서도 용량 하한이 s1 위에 있고, "질문을 알아도 attention
  휴리스틱이 최선이 아니다" — 극한 예산의 write-time 격차는 s1 기준(0.84)보다
  실제로 더 크다. (교환 탐색은 수락 조건상 단조 개선이라 이전 LGO와 달리 search
  audit 통과.)
- 5장의 held-out 결과는 남은 38%p의 상당 부분이 "원리적 예측 불가" 쪽임을 시사한다.
  단 s5가 random보다 17%p 나은 것이 보여주듯 대리 지표의 여지도 실재하며, 질문 없이
  도달 가능한 천장(예: s5 프롬프트 앙상블)은 미확정이다.

## 8. 종합

> 시각 기억의 저장·재사용 자체는 완벽하다(2장). 질문 하나의 근거는 기억의 5%면 충분할
> 만큼 작다(3장). 그러나 그 5%는 질문마다 달라서(4장), 미래 질문을 모르는 저장 시점에는
> 어떤 대리 지표로도 그것을 고르지 못하며(3장, 최소 38%p), 과거 질문을 여러 개 알아도
> 미래 근거는 예측되지 않는다(5장).
>
> **시각 경험 압축의 병목은 저장 용량도 선택 알고리즘도 아니다 — 무엇이 미래에 필요할지가
> 과거로부터 예측되지 않는다는 것이다.**

동결해둔 논문 방향 P1의 성립 문장과 대조:

| P1 조항 | 현재 증거 (전부 파일럿) |
|---|---|
| 좋은 부분집합이 존재 (capacity gap ≤5%p) | s1이 20%에서 0.99 — 존재 증명 완료 |
| 저장 시점 방법이 ≥15%p 잃음 | 38%p (기준의 2.5배) |
| 손실이 한 축에 귀속 (relevance vs 요령) | held-out 붕괴가 relevance를 지목 — T0–T4 층화로 정량화 필요 |
| 독립 모델·데이터에서 재현 | 미실시 (M7) |

같은 held-out 프로토콜(과거 질문 3개의 s1 집합 합집합 → 안 본 질문 평가)을

| **UNION (과거 질문 3개 pool)** | **0.546** | **0.822** |
| (참고) 자기 재현 @5% | 0.937 | — |

| | 문서(DocVQA, n=35질문) | GUI(ScreenQA, n=185질문) |

단, 두 도메인 모두 **자기 재현(0.94)과의 격차는 크다** (GUI에서도 0.55 vs 0.94 —
예측 불가능성 gap은 여전히 지배적). 문서 쪽 표본(35질문)이 작아 도메인 대비 자체는

안 된다. 다만 어떤 도메인에서도 최고 write-time 규칙과 반칙 참조선(s1)의 격차는 크다

"미래 질문을 모른다"는 병목(P1)은 선택 규칙을 바꿔도 사라지지 않는다.

| held-out: UNION−RANDOM | 0%p (과적합) | **+21.1%p** | +5.9%p (유의미하지 않음) |
| random 바닥 (held-out, ~8-10%) | 0.14 | 0.34 | **0.70** |
| 최고 write-time 규칙 (사다리) | s5 (범용) | h2o (이력) | **없음** (전부 random 수준) |
| 거리-유지율 단조 | ✓ (결과 13) | ✓ (결과 13) | **✓ (이번)** |

**추가 (사다리, 같은 날 실행)**: GQA에서 selector 사다리를 돌린 결과, 5% 예산에서
h2o 0.614 / knorm 0.619 / random 0.563 / s5 0.549 — **어떤 write-time 규칙도
random과의 차이가 신뢰구간에서 0을 배제하지 못한다** (h2o−random +5.1%p
[−4.9, +14.8]). 반면 반칙 참조선 s1(0.898)과의 격차는 여전히 크다
(s1−h2o **+28.4%p [21.2, 35.6]**). 즉 자연 이미지 체제에서는 "무엇을 남길지"
신호 경쟁 자체가 무의미해지고, 병목은 오직 질문을 아느냐(s1)뿐이다.

**해석(파일럿)**: 세 도메인은 세 가지 체제다. **문서**는 근거가 넓게 흩어져 있고
중복이 없어 과거 질문 pool이 과적합되고 random도 바닥이다. **GUI**는 근거가 소수
정보 영역에 몰려 pool이 부분 일반화한다(+21%p). **자연 사진**은 장면 중복성이 높아
무엇을 남겨도 웬만큼 되므로 pool의 상대적 가치가 사라진다. 반면 **근거가 이동하면
유지율이 떨어진다는 단조 법칙은 세 도메인 공통**이다 — P1("병목은 미래 질문의 예측
불가능성")의 일반성 주장과, 압축 정책이 도메인 체제를 알아야 한다는 설계 시사점을
동시에 받친다.

## 결과 17. 두 가지 검증 — 자연 사진의 높은 바닥은 "찍기"가 아니고, 집중도 법칙은 GUI 안에서 연속 변수로 성립한다

**(1) 언어 편향 점검 (NO-MEM 기준선)**: 결과 16에서 자연 사진(GQA)은 이미지의 8%만
무작위로 남겨도 0.70을 맞혔다. 이것이 장면 중복성이 아니라 "질문만 보고 찍어서"라면
(GQA는 언어 편향으로 유명한 데이터셋) 해석이 무너진다. 그래서 이미지를 아예 주지 않고
질문 텍스트만 주는 NO-MEM 조건을 세 도메인 전부에서 실행했다.
FULL(이미지 있음) 정답 표본 조건부:

| | 문서(DocVQA) | GUI(ScreenQA) | 자연(GQA) |
|---|---:|---:|---:|
| NO-MEM (질문만) | 0.011 | 0.043 | 0.187 |
| random 8~10% 유지율 (비교) | 0.14 | 0.34 | 0.70 |

GQA의 찍기 성공률은 0.187로 다른 도메인의 4배지만, random 바닥 0.70의 대부분
(~50%p 이상)은 찍기로 설명되지 않는다 → **"자연 사진 = 중복성 체제" 해석 유지**
(단, GQA 수치를 읽을 때 ~19%p의 언어 편향 상한을 항상 병기할 것).

**(2) 근거 집중도를 연속 변수로**: 도메인 3체제(결과 16)는 데이터셋 3개의 대비라
"일화"라는 반박이 가능하다. 이미지마다 근거 상자 좌표가 있으므로, 이미지별
근거 분산(그 이미지 질문 쌍들의 근거 중심거리 평균)이 pool의 추가 가치
(UNION−RANDOM, held-out)를 예측하는지 쟀다.

- **GUI 안에서 성립**: 분산이 큰 화면일수록 pool 가치가 낮다 —
  Spearman **−0.279 [−0.428, −0.122]** (독립 표본으로 잰 중복성을 통제한 부분 상관,
  n=128). 도메인 대비였던 집중도 가설이 이미지 수준의 연속 법칙으로 승격.
- 자연(GQA) 안에서는 유의하지 않음 (−0.111 [−0.326, +0.112], n=84) — GQA는 분산의
  범위 자체가 좁고(평균 0.175 vs GUI 0.282) 이미지당 평가 질문이 2개뿐이라 잡음이 크다.
- **통계 함정 기록**: 중복성(random 바닥)과 pool 가치의 상관을 같은 held-out 표본으로
  재면 −0.57~−0.70의 강한 상관이 나오지만, 이는 두 값이 RANDOM 항을 공유해서 생기는
  **기계적 인공물**이다. 사다리 실험의 random(다른 질문·다른 부분집합 = 독립 표본)으로
  다시 재면 −0.02~−0.12로 사라진다. 이후 분석에서 같은 표본을 예측변수와 결과에
  겹쳐 쓰지 말 것.

## 결과 18. 실패는 예측 못 해도 감지는 된다 — 커버리지 신호와 하이브리드 정책 (A안) ★

**상황**: 지금까지의 결론은 "저장 시점에는 미래 질문의 근거를 못 고른다"였다.
그렇다면 read 시점은 어떤가 — 새 질문이 도착한 순간, 그 질문의 attention 분포 중
**남겨둔 부분집합 위에 떨어지는 비중(coverage)** 은 답을 생성하기 전에 싸게 잴 수 있다.
이 값이 실제 정답/오답을 가려내는지, 기존 held-out·교차 실험의 부분집합을 비트 단위로
재구성해(UNION 크기 4/4 일치 검증) 모든 (기억, 질문) 만남에 coverage를 붙여 쟀다.

**(1) 감지력 (AUROC = 정답 만남이 오답 만남보다 coverage가 높을 확률)**:

| 시나리오 (5% 예산) | GUI | 자연 |
|---|---:|---:|
| 배치 상황: UNION 기억 × 안 본 질문 | **0.786 [0.718, 0.848]** | 0.756 [0.668, 0.836] |
| 전이: 한 질문용 집합 × 다른 질문 | 0.839 [0.808, 0.868] | 0.728 [0.678, 0.774] |
| 전체 (모든 부분집합 종류) | 0.853 [0.837, 0.867] | 0.719 [0.693, 0.745] |

모든 칸이 우연(0.5)을 신뢰구간으로 배제. 20% 예산에서도 0.69~0.81로 유지.

**(2) 하이브리드 정책 미리보기** — "coverage 낮은 질문만 원본 이미지를 다시 읽기"
(폴백 = FULL이므로 조건부 정확도 1.0). 무작위로 같은 비율을 폴백하는 통제와 비교:

| 폴백 비율 | GUI 하이브리드 | GUI 무작위 폴백 | 자연 하이브리드 | 자연 무작위 |
|---:|---:|---:|---:|---:|
| 0% | 0.546 | 0.546 | 0.756 | 0.756 |
| 20% | 0.686 | 0.637 | 0.844 | 0.804 |
| 40% | **0.827** | 0.728 | 0.911 | 0.853 |
| 60% | **0.935** | 0.818 | 0.970 | 0.902 |

GUI에서 40%만 다시 읽으면 격차의 62%가 회수된다(0.546→0.827; 전부 다시 읽기 대비
비용 40%). 모든 폴백 비율에서 커버리지 순서가 무작위 순서를 지배한다.

**의미**: 병목(미래 예측 불가)은 그대로지만, **실패가 근거 이동으로 결정되기 때문에
역으로 read 시점 감지가 가능**하다. "무엇을 남길지"의 범용성은 불가능해도(결과 15·16),
"모자라면 알아채고 되읽는" **정책 수준의 범용성**은 성립할 수 있다 — Phase 2 방법의
뼈대이자 P4(방법이 격차의 ≥60% 회수) 방향의 파일럿 증거. 주의: 폴백의 실제 비용
(prefill 재계산 시간)은 M6에서 측정해야 하며, coverage 계산 자체도 질문 forward 1회가
필요하므로 "공짜 감지"가 아니라 "생성·재읽기보다 싼 감지"다.

## 결과 19. 하이브리드 정책의 실제 비용 (M6 파일럿) — 기억 경로는 TTFT 20배, 원본 보관은 공짜

**상황**: 결과 18의 하이브리드 정책이 실제로 남는 장사인지, V100 1장·batch 1·fp16에서
두 경로의 벽시계 시간을 쟀다 (도메인당 10이미지, 3회 반복 후 기록, decode 16토큰).
경로 A = 저장된 KV 위에 질문 토큰만 prefill 후 생성. 경로 B = 이미지 재읽기
(vision 인코더 + 전체 prefill) 후 생성.

| GUI(ScreenQA, 시각 토큰 ~1222) | 첫 토큰까지(TTFT) | 총(16토큰) |
|---|---:|---:|
| 경로 A (기억, 5% 보관) | **0.061s** | 0.98s |
| 경로 B (이미지 재읽기) | 1.26s (**20.5배**) | 2.18s |

자연(GQA, 토큰 ~225)은 이미지가 작아 격차도 작다: TTFT 0.061s vs 0.30s(4.8배),
총 0.97s vs 1.21s. **decode 시간은 두 경로가 같으므로**(0.92s) 절약은 전부
prefill에서 나온다 — 긴 입력일수록 기억 재사용이 유리하다는 뜻.

**저장 비용의 역설**: 원본 이미지 파일(127KB)이 5% KV(3.3MB)보다 **27배 작다**
(전체 KV는 66.8MB). 즉 폴백용 원본 보관은 사실상 공짜이고, KV를 저장하는 이유는
바이트 절약이 아니라 **재계산 시간(prefill) 절약**뿐이다 — "KV 메모리 폭발" 동기가
아니라 TTFT/FLOPs 동기가 정직하다는 기존 판단(M6 §4)의 실측 확인.

**정확도-지연 곡선 (GUI, 5% 기억, 결과 18의 폴백 표와 결합)** — 감지 비용은 기억
경로의 질문 prefill과 같은 forward라 추가 0:

| 폴백 비율 | 정확도 | 기대 지연 | 항상 재읽기 대비 |
|---:|---:|---:|---:|
| 0% (기억만) | 0.546 | 0.98s | 45% |
| 40% | 0.827 | 1.49s | 68% |
| 60% | 0.935 | 1.74s | 80% |
| 100% (항상 재읽기) | 1.000 | 2.24s | 103% |

**의미**: 커버리지 순서 폴백은 60% 폴백에서 정확도 0.935를 재읽기 비용의 80%로 얻는다.
단서: batch 1·eager attention·V100 단일 조건이며, 16토큰 답변 기준이라 decode가
길어지면 상대 이득이 줄어든다. 서빙 배치·다른 하드웨어의 곡선은 본실험에서.

**부록 (2026-08-18): "KV가 이미지보다 커서 대역폭이 병목 아닌가" 실측** —
콜드 상태(디스크 캐시 비움)에서 SSD→RAM→GPU 로드 시간: KV 5%(3.3MB) **40ms** /
20%(13.3MB) 30ms / 전체(66.8MB) 143ms — 재인코딩 1.26s 대비 9~42배 여유.
바이트 이동(GB/s 파이프)과 재계산(GPU 1.26s)은 단위가 다르다: 이미지 파일은
옮기기엔 27배 싸지만 옮긴 뒤 1.26s짜리 계산 고지서가 따라온다. 하이브리드 TTFT는
로드 포함 ~0.1s로 여전히 12배 빠름. 고QPS 극한에서는 페이지 캐시(재읽기 디스크
비용 0)와 양자화(4~8배 축소)가 한계를 밀어올린다.

전 세트 ≥0.73으로 관문(0.70) 통과. **자연 도메인에서는 a4가 반칙 상한마저 넘는다**

자백한다. 사전 판정형(attention)보다 사후 검증형이 강하다는 것: speculative
decoding의 draft-검증 정신(아이디어 3)이 이 방법의 최적 형태라는 뜻.
엔트로피·sink 신호는 약했고, 이미지별 자기 보정(후보 5)은 원신호보다 나빴다
(기준점 1개의 잡음; a4는 애초에 눈금이 안정적이라 불필요).

**(2) 관문 2 — 임계값 교차 보정**: Q2.5×GUI의 절반에서 "폴백 40%" 지점의
임계값 τ=1.914 하나를 동결하고 나머지 전부에 그대로 적용:

| 적용 대상 | 폴백률(드리프트) | 하이브리드 정확도 | 폴백 없음 | 무작위 폴백이면 |
|---|---:|---:|---:|---:|
| Q2.5×GUI (원점) | 40% | **0.838** | 0.546 | 0.728 |
| Q2.5×자연 | 59% | 0.963 | 0.756 | 0.900 |
| Q3×GUI | 34% | 0.755 | 0.500 | 0.670 |
| Q3×자연 | 28% | 0.928 | 0.826 | 0.875 |

**숫자 하나가 다른 모델·다른 도메인에서 파국 없이 작동**하고(폴백률 28~59% 밴드),
네 세트 모두 같은 비율의 무작위 폴백을 지배한다. 배포형 신호의 하이브리드(0.838)가
반칙 coverage의 하이브리드(0.827, 결과 18)와 동급 — **반칙을 제거해도 성능 손실이
없다.**

**의미**: 하이브리드 방법(아이디어 4)의 마지막 미검증 조건이 채워졌다. 최종 형태는
"질문 도착 → 저장된 조각으로 **첫 답 토큰만 생성**(0.06초) → 확신도가 τ 미만이면
원본 이미지 재읽기" — 추가 계산이 사실상 0이고, 훈련이 필요 없으며, 어떤 압축
방식 위에도 얹힌다. 논문 §3의 방법이 확정됐다 (PAPER-PLAN §4 분기: 통과 경로).

## 결과 22. 검증된 초안 재사용 (방법 1단) — 수락률도 단조 법칙을 따르고, 반복형 워크로드에서 질의의 42%를 16배 빠르게 처리한다

**상황**: 방법의 1단(아이디어 3 완성형)을 검증했다. 기억 옆에 저장해둔 과거 질문의
답(FULL 이미지에서 생성된 것)을 새 질문의 초안으로 넣고, 보관 KV(UNION@5%) 위에서
[질문+초안]을 forward 1회로 병렬 검증 — 모든 초안 토큰이 greedy 일치하면 수락.
수락된 답은 2단(생성 경로)이 냈을 답과 동일함이 보증된다 (0.06s vs 0.98s = 16배).

**(1) 수락률은 근거 겹침에 단조** — 단조 법칙의 네 번째 발현:

| 쌍 라벨 | 자연(GQA) 수락률 | GUI(SQA) 수락률 |
|---|---:|---:|
| 같은 근거·같은 답 | **0.502** | (표본 2) |
| 부분 겹침 | 0.103 | 0.133 |
| 다른 근거 | 0.079 | 0.053 |

관련 없는 질문의 답은 거의 수락되지 않는다(5~8%) — 검증기가 안전판 역할을 실제로
수행하며, 그 안전성의 원리가 본문의 단조 법칙과 같다.

**(2) 질문 단위 효과** (후보 초안 = 소스 질문 3개의 답, margin 최대 수락분 채택):

| | 수락된 질문 비율 | 수락답 정답률 | 의미 |
|---|---:|---:|---|
| 자연(GQA, 반복형 워크로드) | **42.2%** | 0.509 | 질의 42%가 0.06s 경로로 |
| GUI(SQA, 반복 드묾) | 17.9% | 0.385 | 반복성 낮으면 이득도 축소 |

수락답 정답률은 2단이 같은 질문에 냈을 정답률과 같다(보증의 정의) — 1단은
**정확도를 바꾸지 않고 지연만 줄인다.** 평균 지연 절감: GQA에서 질의당
0.42×(0.98−0.06) ≈ **0.39초** (1·2단 구간 기준).

**의미와 한정**: 이득은 비슷한 질문이 반복되는 워크로드에 비례한다 — GQA(같은근거
쌍이 많음) 42% vs SQA 18%. 멀티턴 QA라는 우리 motivation 무대가 정확히 전자다.
시맨틱 답 캐시(유사도만으로 반환)와 달리 잘못된 초안이 조용히 나가는 일이 구조적으로
없다. margin 임계값을 더 얹으면 수락률↔수락 정답률을 조절할 수 있다(기록됨, 승격에서
곡선으로). 이로써 3단 사다리의 세 단이 모두 데이터로 뒷받침됐다:
1단(이번) + 2단(결과 21) + 3단(결과 19).

## 결과 24. 게이트형 시각 기억 — 세 게이트 전부 훈련 없이 성립 (2026-08-19, GPU 2·3 로컬 실행) ★

**프레임**: 장기 시각 기억을 LSTM의 동작 원리처럼 — 입력 게이트(무엇을 몇 byte로 쓸까) / 망각 게이트(무엇을 낡음 처리할까) / 출력 게이트(무엇을 읽을까)가 흐름을 제어하는 시스템으로 — 설계. 단 저장은 잠재 벡터가 아니라 명시적 계층(사진 아카이브/텍스트/핫 캐시). 상세: `docs/GATE-VERIFICATION.md`, 원데이터: `results/discovery/gates/`.

1. **입력 게이트**: 이미지별 필요 예산(전체 화질 답 유지 최소 byte)이 GUI에서 16배 편차. 공짜 신호(원본 파일 크기 ρ=0.68, 해상도 0.62)로 예측 가능. 같은 총예산 배분 시뮬레이션(미래 점수 차단, 5-fold)에서 **빠듯한 예산(GUI 8KB/장)일 때 균등 0.261 → 게이트 0.436(+67%, 오라클 상한 도달)**. 예산이 넉넉하면 이득 소멸(적용 조건 명확). 자연 이미지는 오라클 +5.2pp가 있으나 현 신호로 미실현.
2. **망각 게이트 감지기**: 옛/새 화면 96쌍(시각·스냅샷 번호가 매 쌍 달라 "픽셀 다름=낡음"은 반칙인 설계)에서 내용영역 타일 비교기가 AUROC 1.0, 위치까지 48/48, 쌍당 30ms CPU. 한계: 픽셀 정렬된 합성 화면.
3. **망각 게이트 실전 (2배 규모)**: 확장 픽스처 64ep×10 trial 전량 실행. 변경된 에피소드에서 낡은-기억 조건이 **32/32 옛 값을 답함**(조용한 거짓말, 누적 48/48). 감지기 결합 게이트 정책 = **정확도 1.000**. "둘 다 보관"도 1.0이지만 저장 2배·읽기 2.1s vs 게이트 1.1s. AVIF 압축(평균 21.6KB, 1/10)에서도 전 수치 동일 — 결론은 압축률 독립. 검색·간섭(d3)은 확장판에서도 전 셀 만점 → 이 규모의 실패는 오직 시간축.
4. **출력 게이트**: 기검증(a4 확신도 AUROC 0.73~0.81, 캐스케이드).

**의미**: motivation ①(낡음 관리)+②(적응 예산)이 하나의 설계 언어(게이트)로 통합되고, 세 게이트 모두 학습 불필요(학습형 선행 TaskMem +5~7%와 차별). 남은 승격 조건: 실환경 GUI 정렬, 자연 이미지 입력 신호, 승격/강등 진동 안정성.
