# Phase 1 파일럿 결과 종합 (2026-08-13 ~ 08-14)

> **이 문서의 지위**: 모든 수치는 `smoke`(파일럿) 표본이다 — DocVQA 문서 32장, seed 1개,
> 질문 쌍 유형 라벨(T0–T4) 없음, 이미지 단위 신뢰구간 없음. SHARED_PROTOCOL 규칙에 따라
> discovery/confirmation 결과로 승격하지 않고 E/S/N/I 판정을 매기지 않는다.
> 방향 신호는 선명하지만(주 격차가 측정 잡음의 15배 이상), 논문 수치가 되려면
> 라벨링 → 표본 확대 → 동결된 본실험 절차가 남아 있다.

## 0. 배경과 용어

**연구 질문**: VLM 에이전트가 과거에 본 이미지를 원본 대신 압축된 기억으로 저장했다가
나중에 재사용할 때, 성능 손실이 언제·왜 발생하는가?

| 용어 | 뜻 |
|---|---|
| KV | 모델이 이미지를 읽을 때 생기는 중간 계산 결과. 시각 토큰당 1개(문서 사진당 약 1,260개). 이걸 저장해두면 이미지를 다시 계산하지 않고 재사용 가능 |
| 압축 (예산 B) | KV 중 B%만 남기고 지우는 것. 예산은 직렬화 bytes 기준(색인·위치 정보 포함) |
| selector | "어느 토큰의 KV를 남길지" 고르는 규칙 |
| 대리 지표 | 미래 유용성은 잴 수 없으므로, selector가 대신 쓰는 근사 신호 (아래 3부) |
| EM / ANLS | 채점 지표. EM = 정답 완전 일치, ANLS = DocVQA 공식 편집거리 유사도 |
| 유지율 | 무압축 기억이 맞힌 질문 중, 압축 후에도 맞히는 비율 (조건부 — 모델이 원래 못 푸는 문제를 압축 탓으로 세지 않기 위함) |
| V2 | 정보를 지우는 시점을 "질문 도착 전"으로 고정한 측정 방식 (아래 1부-③) |

## 1부. 측정의 자격 — 도구가 아니라 현상을 재고 있음을 확인 (M0)

**① 모델의 기본 능력은 과제별로 다르다.** 이미지를 직접 보여줬을 때: 글자 읽기·색깔·
좌우 배치 = 100%, 좌표 짚기 = 60%. 좌표의 잔여 실패는 형식 문제가 아니라 **화면 상단
물체의 y좌표를 아래로 밀어 답하는 모델의 체계적 편향**이다 (실패 4건 중 3건이 상단→하단
패턴, x축은 정확). → 좌표 과제는 조건부 유지율 규칙으로 다룬다.

**② 과제는 실제로 이미지에 의존한다.** 시각 정보를 전부 차단하면 점수 −0.78,
정답 로그확률 −11.4 nats. 이미지 없이 질문만 주면 0%. → "기억이 없으면 못 푸는"
과제 집합임이 성립.

**③ 지우는 시점이 늦으면 점수가 4배 부풀려진다 (정보 밀수).** 입력은
[시스템, 이미지, 질문, 답] 순서인데, 질문 토큰은 처리 중에 이미지를 참조하므로 **질문
자신의 KV에 이미지 정보가 섞여 든다**. 이미지를 100% 지워도, 지우는 시점이 "질문이
이미지를 본 뒤"(V1)면 이 우회로로 점수 0.50이 나온다. "질문 도착 전"(V2)이면 0.12.
→ V1로 재면 압축 손실을 크게 과소평가한다. 모든 실험은 V2로 고정 (초기 실험이 무효
처리된 이유이기도 하다).

**④ 측정 잡음의 크기: 로그확률 ~0.15 nat.** 계산 경로를 합법적으로 바꿔도(저장→디스크→
복원→이어 계산, 쪼개서 계산) 이 이상 차이가 나지 않고, 모델의 답 선택은 40/40 불변.
2D/4D 경로와 100% 보존 검사는 차이가 정확히 0. → 이보다 작은 차이는 효과로 해석 금지
(동결 허용오차 0.5의 근거).

## 2부. 압축하지 않으면 아무 문제가 없다 (M1)

DocVQA 8문서 16질문:

| 조건 | 정답률 |
|---|---:|
| 기억 없음 (질문만) | 0.00 |
| 원본 이미지 재인코딩 | 0.94 |
| **무압축 KV 저장→디스크→복원→주입** | **1.00** |
| 시각 KV만 (시스템 prefix 행 제외) | 0.75 |
| 질문 위치를 +2048 토큰 밀어 주입 | 0.94–1.00 |

- **저장·재사용 경로 자체는 완벽하다** — 이후의 모든 실패는 압축 때문이다.
- 방향 신호 2개: (a) 시각 부분만 저장하면 하락 — 기억의 단위가 시각 블록보다 클 수
  있음(M1-D 가설). (b) 기억-질문 간 거리 증가 단독으로는 안 깨짐 — 단, 압축과의
  상호작용·실제 텍스트 삽입 시 간섭·기억 블록 재배치는 별개 질문으로 남음.

## 3부. 압축하면: 어떤 대리 지표를 쓰든 강한 압축에서 실패한다 (M2-A)

모든 저장 시점 selector는 "미래 유용성"을 대리 지표로 근사한다. 20% 예산에서의
유지율 (FULL 정답 89질문 기준):

| selector | 대리 지표 | 유지율@20% |
|---|---|---:|
| random | 없음 (하한) | 0.44 |
| spatial_uniform | 위치 (골고루) | 0.45 |
| knorm | key 벡터의 크기 | 0.17 † |
| **s5** (KVzip 적응) | **범용 과제("전체를 설명하라")에의 쓸모** | **0.61** |
| h2o (H2O 적응) | 과거 대화(질문+답)에서 실제 쓰인 정도 | 0.51 |
| s1 — read-time 참조선 | (반칙) 미래 질문 자체의 attention | 0.99 |

† knorm은 무작위보다 나쁨 — 텍스트 LLM 휴리스틱이 시각 KV에 이식되지 않는다는 부정적
신호. 단 적응 구현의 부호 관례 검증 전이므로 주장 보류.

**전체 예산 곡선** (s1과 random, 5%까지 확장):

| | 5% | 10% | 15% | 20% | 40% | 60% | 80% |
|---|---:|---:|---:|---:|---:|---:|---:|
| s1 | 0.84 | 0.90 | 0.93 | 0.99 | 1.00 | 0.99 | 0.99 |
| random | 0.18 | 0.25 | 0.34 | 0.44 | 0.70 | 0.82 | 0.94 |

핵심 관찰 세 가지:

1. **용량은 병목이 아니다.** 질문을 알면 5% 예산(1,260토큰 중 62개)으로 84%를 지킨다.
   절벽 없이 완만히 내려올 뿐이다. 질문 하나의 근거는 극히 작은 조각에 담긴다.
2. **저장 시점에는 아무도 그 조각을 못 고른다.** 최고 대리 지표(s5)조차 20%에서 0.61.
3. **약한 압축(80%)에서는 문제가 거의 없다** (0.85–0.96). 이 실패는 강압축(5–40%)의
   현상이다.

## 4부. 실패의 원인: 미래 근거는 과거로부터 예측되지 않는다 (M3 파일럿)

같은 문서의 질문들 사이에서 s1 부분집합을 주고받아 보았다.

| 조건 | ~5–9% 크기 | ~20–29% 크기 |
|---|---:|---:|
| 자기 재현 (질문 A의 집합 → A) | 0.84 | 0.99 |
| **교차 (A의 집합 → 다른 질문 B)** | **0.24** | **0.59** |
| 합집합(질문 1–3) → **그 세 질문** | 0.85 (9.5%) | 0.99 (29.5%) |
| 합집합(질문 1–3) → **안 본 질문 4–5** | **0.14** (9.2%) | **0.54** (28.5%) |
| (대조) 같은 크기 무작위 → 안 본 질문 | 0.14 | 0.40 |
| (대조) 같은 크기 s5 → 안 본 질문 | 0.29 | 0.43 |
| (기준) 안 본 질문의 무압축 정답률 | 0.83 | 0.83 |

네 단계의 논증:

1. **한 질문용 집합의 재사용은 붕괴한다**: 0.99 → 0.59 (20%, **40%p**). 텍스트에서
   KVzip이 보고한 붕괴(35%p)와 같은 현상·유사한 규모를 시각 기억에서 통제 재현.
2. **아는 질문들의 합집합은 완벽하다**: 세 집합은 1/3쯤 겹쳐(Jaccard 0.33) 합쳐도
   9%뿐인데 세 질문을 전부 커버(0.85→0.99). — 여기까지만 보면 "작은 만능 pool"이
   존재하는 듯하다.
3. **그러나 안 본 질문에서 그 pool은 무작위다**: 9% 크기에서 0.14(무작위와 동일),
   29%로 키워도 유지율 65%. **과거 질문 3개를 아는 것이, 질문을 하나도 안 쓴 범용
   신호(s5, 0.29)보다도 나쁘다.** — "만능"처럼 보였던 것은 아는 질문들에 대한
   과적합이었다.
4. **실물 예시** (ITC 광고 문서): pool은 소스 질문들의 근거(연도, 퍼스널케어 브랜드…)만
   담았고, 안 본 질문 "의류 브랜드 2개는?"에 모델은 지워진 근거 대신 **남아 있는 다른
   브랜드 이름("Classmate and Paperkraft")을 그대로 다시 답했다** — 근거가 지워진
   기억의 실패는 "모른다"가 아니라 "남은 것으로 그럴듯하게 오답"의 형태로 나타난다
   (정확도 외에 행동 왜곡·loyalty 문제의 실물).

**결론(파일럿 수준)**: 저장 시점 선택의 실패는 "고르는 요령이 나빠서"가 아니라
**"미래 질문이 요구할 근거가 과거 경험(질문 이력 포함)으로부터 예측되지 않아서"**다.

## 5부. 격차의 해부 — 지금까지의 수치를 하나의 그림으로

20% 예산 기준:

```text
random 0.44 ────────────── s5 0.61 ────────────────────────── s1 0.99 ── (진짜 최적 ≤1.00)
        └── 17%p: 대리 지표 개선이 └── 38%p: 남은 격차 —
            이미 닫은 부분              "더 좋은 지표가 있는데 못 찾은 것"인가,
            ("요령의 몫")               "원리적으로 예측 불가"인가?
```

- s1은 진짜 최적(oracle)이 아니라 그 **하한**이다 (s1 ≤ oracle ≤ 1.00). 20%에서는
  s1=0.99라 위 공간이 1%p뿐 → **"최소 38%p"는 사실상 확정**. 5%에서는 s1=0.84라
  위로 16%p가 미확정 — oracle이 높을수록 격차는 더 커진다.
- 4부의 held-out 결과는 남은 38%p의 상당 부분이 "원리적 예측 불가" 쪽임을 시사한다.
  단, s5(0.61)가 random(0.44)보다 분명히 나은 것이 보여주듯 대리 지표의 여지도
  실재하며, 질문 없이 도달 가능한 천장이 어디인지는 미확정이다.

**방법론 부산물 — answer-aware probe의 탐색 실패**: "정답까지 주고 최적 조각을
찾아오라"던 진단 도구가, 한 조각씩 가려보는 탐색(leave-group-out) 때문에 실패했다.
근거가 중복되면 낱개 제거의 피해가 전부 0으로 보여(비가산성) 순위가 무의미해진다 —
실제로 모든 조각의 하락값이 0이었고 probe 성적은 예산과 무관하게 0.75로 평평, 같은
질문에서 s1이 1.00을 달성했으므로 상한일 수 없다. 계획서의 search-audit 규칙에 따라
**판정 불가(I)로 폐기**. 낱개 점수가 아니라 집합 단위로 평가하는 탐색(교환 탐색)으로
교체 예정이며, 이는 "중요도는 집합의 성질"이라는 이 연구의 반복 교훈과 같은 결이다.

## 6부. 종합 서사와 논문 방향 대응

> 시각 기억의 저장·재사용 자체는 완벽하다(2부). 질문 하나의 근거는 기억의 5%면 충분할
> 만큼 작다(3부). 그러나 그 5%는 질문마다 달라서(4부-1), 미래 질문을 모르는 저장
> 시점에는 어떤 대리 지표로도 그것을 고르지 못하며(3부, 최소 38%p), 과거 질문을 여러 개
> 알아도 미래 근거는 예측되지 않는다(4부-3). — **시각 경험 압축의 병목은 용량도 선택
> 알고리즘도 아닌, 미래 관련성의 예측 불가능성이다.**

동결된 논문 방향(P1, DECISIONS §12) 성립 문장과의 대응:

| P1 조항 | 현재 증거 (전부 파일럿) |
|---|---|
| capacity gap ≤ 5%p (좋은 subset 존재) | s1이 20%에서 0.99 달성 — 존재 증명 완료 |
| write-time selector가 ≥15%p 잃음 | 38%p (기준의 2.5배) |
| 손실의 2/3 이상이 한 축에 귀속 | held-out 붕괴가 relevance 축을 지목 — T0–T4 층화로 정량화 필요 |
| 2개 모델 계열·2개 데이터셋 재현 | 미실시 (M7) |
