## 1. fp16 NaN의 근본 원인 확정과 해결 (M0-04)

### 1.1 문제

Qwen2.5-VL-7B fp16 실행에서 특정 입력의 logits가 NaN이 되어 legacy D4 실험이
중단됐다 (`archive/results/d4_mini/shard0.log`). 종전 대응은 "LLM layer 27만
fp32로 실행"이었으나 그 패치 뒤에도 재발했다.

### 1.2 원인 (실측)

HuggingFace eager attention은 다음 순서로 계산한다.

```text
attn = matmul(Q, K^T) * (1/√d)      ← 곱셈이 먼저, 스케일링이 나중
```

**스케일링 전의 `QK^T`가 fp16 matmul 출력 한계(65,504)를 넘으면 inf가 되고,
softmax에서 NaN이 된다.** layer별 실측 (doc4733, `results/smoke/nan_diagnosis/`):

| layer | 스케일 후 max\|logit\| | 스케일 전 (×√128≈11.3) | fp16 한계 대비 |
|---:|---:|---:|---|
| 0 (문제의 q1) | 6,145 | ≈ 69,500 | **초과 → NaN** |
| 0 (다른 질문들) | 4,535–5,091 | ≈ 51k–58k | 아슬아슬하게 통과 |
| 27 (모든 입력) | 10,475–10,901 | ≈ 118k–123k | **상시 초과** — 종전 layer-27 fp32 패치가 통했던 이유 |

결정적 증거 두 가지:

1. 문제 입력(q1)은 **마스크를 전혀 쓰지 않은 평범한 2D 경로에서도 NaN** —
   즉 4D mask/position 장치의 문제가 아니라 라이브러리 계산 순서의 문제.
2. mask_rows 검사(모든 query 행에 유효 key 존재)는 전 조건 통과 —
   "전부 가려진 행" 가설 기각.

### 1.3 처방과 검증

수학적으로 동일한 `(Q × 1/√d) @ K^T` 순서로 교체 —
`vlm_diagnosis/core/loader.py`의 `patch_stable_qk_scale()` (기본 적용).
스케일 후 최대값 ≈ 11k는 fp16 범위에 충분한 여유가 있다.

- 원래 실패하던 입력 포함 doc4733 4질문 전부 finite, **fp32 layer 없이** 통과.
- 전수 검증: **32문서 × 4질문 × 3경로 = 384/384 finite**
  (`results/smoke/nan_diagnosis/sweep.jsonl`).
- layer-27 fp32 패치는 retire (`LEGACY_FP32_LAYERS`로 진단 비교용만 보존).
- `assert_finite_logits` 가드는 전 실험 유지 (새로운 입력 분포 대비).

기록: DECISIONS.md §14 (M0-04), commit `42c9102`.

**함의**: 기존에 "layer 27이 특이하다"고 알던 것은 증상이었고, 병인은 attention
스케일링 순서 하나였다. 이후 모든 수치는 이 패치 하에서 측정된다.

### 2.1 허용오차(M0-01)의 실측 근거

M0-E1/E2의 0.13–0.16 nat 차이는 오류가 아니라 **fp16에서 GEMM 형상이 바뀔 때의
불가피한 반올림 누적**이다 (같은 행이라도 행렬 크기가 다르면 누적 순서가 다름).
중요한 것은 이 잡음 대역에서 **greedy 예측이 40/40 전부 동일**했다는 점 —
잡음이 결론을 바꾸지 않는 수준임을 뜻한다.

제안 임계값 (m0.yaml `proposed_*`, 실측 worst의 ~3배 여유):

```text
strict_logit_max_abs      : 0.5   (실측 worst 0.155)
operational_logit_max_abs : 0.5   (실측 worst 0.141)
strict_cache_max_abs      : 4.0   (실측 worst 1.08)
```

동일 입력 반복이 아니라 **합법적 계산 변형(직렬화 왕복, chunked prefill)의 분포**로
잰 값이므로 PLAN §2.1의 "반복 실행만으로 noise floor를 정하지 않는다" 규칙을
만족한다. 확정(M0-01)은 사용자 결정 대기.

### 2.2 부수 관찰

- 커스텀 4D-mask greedy 생성기(`core/masked_generate.py`)가 HF `generate`와
  ocr/icon/layout 30/30 동일 출력 — 구현 자기검증. grounding의 긴 자유 생성에서만
  7/10 표현 분기 (같은 잡음 대역에서 근소차 토큰이 갈리는 자연 현상; teacher-forced
  예측 일치는 40/40이므로 측정 계약과 무관).

## 3. V1/V2 smuggling 정량화 (M0-F)

**정의**: 입력은 `[시스템][이미지][질문][답]` 순서이고, 질문 토큰은 처리 중에 이미지
토큰을 attend하므로 **질문 토큰의 KV 안에 이미지 정보가 섞여 들어간다**.

- **V1 (오염 경로)**: 답 생성 시점부터 이미지 KV 차단 — 질문은 이미 이미지를 봤고,
  답은 "이미지를 본 질문의 KV"를 통해 정보를 우회 수급.
- **V2 (기본 semantics)**: 질문 도착 전부터 차단 — 실제 시나리오("과거에 압축·저장,
  미래에 새 질문")와 일치.

실측 (이미지 정보 100% 삭제 상태):

| 경로 | task 점수 | Δlogp (2표본 debug) |
|---|---:|---:|
| V1 | **0.50** | −21 ~ −23 |
| V2 | **0.12** | −34 ~ −36 |

V1은 삭제된 정보의 상당 부분을 우회로로 회수한다 (task 4배, logp ~13 nats).
**V1로 압축 실험을 측정하면 손실을 크게 과소평가**한다 — legacy D4가 무효 처리된
이유 중 하나이며, 이후 전 실험은 V2로 고정한다 (V2 점수 0.12가 0이 아닌 것은
좌/우·색깔류 4지선다성 과제의 추측 성공분).

## 4. grounding base 0.20 → 0.60 — 실패 원인 분석

1차 실행에서 grounding(좌표 짚기) base가 0.20으로 나왔으나, 예측을 뜯어보면
**능력 실패가 아니라 응답 형식 문제**였다: 모델이 장황하게 서술하다가
`max_new_tokens=24`에 잘려 좌표를 내기 전에 중단됨 (좌표까지 도달한 2건은 만점).
질문을 "좌표만 답하라"로 고치고 32토큰으로 늘리자 0.60.

잔여 0.4의 실패는 Qwen2.5-VL이 점 좌표보다 **bbox 형식 출력에 맞춰 학습된 관례**와
관련된 것으로 보이며, M0-02/03에서 프롬프트·판정(박스 중심 허용) 1회 반복 후
기준선을 확정해야 한다. **교훈: 생성 기반 평가에서는 프롬프트·토큰 상한이 측정
계약의 일부다** — M2-A의 생성 metric 설계에 동일 규칙 적용 (answer-brevity 지시).

## 5. M1 — 무압축 저장·재사용 첫 결과 (8문서 16질문, DocVQA)

runner: `vlm_diagnosis/exps/m1_storage_reuse.py`.
write = `[시스템][이미지]` prefix만 forward(질문 무관, M1-01 권장 경계) →
KV+위치 metadata 직렬화 → read 시 이미지 없이 주입 + 새 질문.

| 조건 | 뜻 | EM |
|---|---|---:|
| NO-MEM | 기억 없이 질문만 | **0.00** |
| IMAGE | 원본 이미지 재인코딩 (기준선) | 0.94 |
| **STORED-FULL** | 저장 KV 주입 (동일 offset) | **1.00** |
| STORED-KV-ONLY | 시스템 prefix 행을 뺀 시각 KV만 | **0.75** |
| CTX-SHIFT | write 시 system 문구 변형 | 0.94 |
| OFFSET +128/+512/+2048 | 질문 위치만 뒤로 밀기 (naive, 재회전 없음) | 0.94–1.00 |

### 해석 (smoke 지위 하에서)

1. **M1-A gate 통과**: 직렬화→디스크→로드→주입 전체 경로가 IMAGE 동등 성능을
   재현한다. DECISIONS §3 규칙대로 이는 연구 발견이 아니라 **구현 자격**이다.
   이후 M1-B/C의 차이는 구현 탓으로 돌릴 수 없게 됐다.
2. **NO-MEM 0.00**: 과제가 실제로 이미지 의존적 — retention 측정의 전제 성립.
3. **K_v-only 0.75 (−25%p)**: prefix(시스템 토큰) KV를 빼면 하락. "재사용 가능한
   기억의 단위가 visual block보다 클 수 있다"(M1-D 가설)의 첫 방향 신호.
   단 n=16, 관대한 metric — canonical 본실험에서 재측정할 것.
4. **naive offset 견고**: 기억-질문 간 상대 거리를 +2048까지 늘려도 EM 유지.
   주의 — 이것이 말하는 것은 "위치 번호 이동 *단독*은 장애물이 아니다"까지다.
   (a) 압축과의 상호작용, (b) 실제 텍스트 삽입 시 간섭(M5), (c) 기억 블록 자체의
   재배치(재회전 필요, M1-C 본실험)는 전부 별개 질문이며 이 결과의 근거 범위 밖이다.
